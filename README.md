# RAG Analytics over Governed Data

**An AI analytics assistant that answers questions about warehouse metrics and
tables — and refuses to answer when the governed catalog has no evidence.
Hallucination control is the product, not the plumbing.**

> The corpus is **synthetic** (generated by `data/generate_governed_docs.py`):
> table docs, metric definitions, and a glossary that play the role of a real
> data catalog / dbt docs site. No employer data is included.

## Architecture

```mermaid
flowchart LR
    A[data/corpus/*.json\ngoverned docs] --> B[src/chunking.py\nsentence chunks, token budget]
    B --> C[src/embeddings.py\nMockEmbedder offline\nAPIEmbedder in prod]
    C --> D[src/retrieval.py\ncosine search + citations]
    D --> E[src/answer.py\nguardrailed answers]
    E --> F[refuse if score < threshold\nelse answer + [sources]]
    G[src/eval.py\noffline retrieval eval] --> D
```

## The Why

LLMs hallucinate most when underlying data is poorly governed — vague metric
definitions, undocumented tables, tribal knowledge. Ask "how is Missed Pickup
% calculated?" and a raw LLM will invent a plausible formula. This project
demonstrates the fix data teams actually need: retrieval constrained to a
governed catalog, every claim cited to a document, and an explicit refusal
when the catalog has no evidence. A confident wrong number is worse than no
number.

## Tech decisions & trade-offs

- **Governance-first, not model-first:** the differentiator isn't a better
  LLM, it's that answers can only come from catalog documents. This is the
  pattern that minimizes hallucinations from poor-quality data.
- **MockEmbedder default:** hash-based, deterministic, zero cost, zero
  network — the full pipeline (index → retrieve → answer → evaluate) runs
  anywhere, including CI. The `Embedder` interface means swapping in a real
  provider changes one line and touches nothing else.
- **Extractive answering offline:** the default answerer stitches source
  sentences rather than generating text, so citations are provably faithful.
  The production upgrade is an LLM call with retrieved chunks as the *only*
  context — guardrails unchanged.
- **Score-threshold refusal:** a tunable `MIN_SCORE` below which the system
  refuses. Tunable beats hardcoded; the threshold is documented and tested.

## Setup & run

Prerequisites: Python 3.10+. No API keys needed for the default offline mode.

```bash
make setup   # installs deps, copies .env.example -> .env
make data    # generate the synthetic governed corpus
make index   # build the retrieval index
make eval    # run the offline retrieval eval
make test    # run the pytest suite
```

Try it:

```bash
python - <<'EOF'
from src.answer import answer_question
from src.embeddings import default_embedder
from src.retrieval import Retriever

embedder = default_embedder()
retriever = Retriever.build(embedder)
for q in ["How is Missed Pickup % calculated?",
          "What is the capital of France?"]:
    a = answer_question(q, retriever, embedder)
    print("Q:", q, "\nA:", a.text, "\n")
EOF
```

Expected output: a cited answer for the metric question, and an explicit
refusal for the out-of-scope question.

## Synthetic data strategy

`data/generate_governed_docs.py` writes the entire corpus (table docs, metric
definitions, glossary) with fixed content. There is no path for real employer
or customer data: the generator is the only writer, and nothing leaves the
repo (no API calls in default mode).

## Limitations & roadmap

- `MockEmbedder` proves the pipeline runs; it is not semantically strong.
  Real retrieval quality needs a real embedding model (`APIEmbedder` seam).
- Extractive answers are faithful but terse; generative answers need an LLM
  call with strict context-only prompting.
- Roadmap: hybrid search (BM25 + vectors), chunk-level access control
  (per-role catalog visibility), eval set grown from real support questions.

## Tests & CI

- **Chunking tests:** token budget respected, sentences never split mid-way,
  every chunk carries its source `doc_id`.
- **Retrieval tests:** the relevant doc ranks first, scores bounded, answers
  cite their sources.
- **Guardrail tests:** out-of-scope questions are refused with an explanation;
  in-scope questions are never refused. These run in CI on every push, along
  with the offline retrieval eval.
